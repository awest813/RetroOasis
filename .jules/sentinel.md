## 2024-08-15 - Prevent DOM-based XSS in static HTML Error Messages
**Vulnerability:** Untrusted user input via the `rom` URL parameter (which acts as a file path or name) and the `back` URL parameter were being dynamically inserted into the DOM using string interpolation for `innerHTML`. Specifically, the custom `escapeHtml` function was insufficient to prevent unsafe URL injection on the `back` navigation button (`href="javascript:..."`), and error messages containing dynamic HTML logic could lead to XSS if not escaped completely safely.
**Learning:** In static HTML files without a robust framework (like React or a bundler), creating elements by interpolating variables into `innerHTML` is high-risk. Simple string `escapeHtml` functions can easily be bypassed or misapplied when constructing complex HTML nodes like `<a>` tags with `href` properties.
**Prevention:** Avoid `innerHTML` entirely when handling dynamic text, even in static HTML contexts. Use `document.createElement`, `document.createTextNode`, and build node trees natively (e.g. using `DocumentFragment` for formatting like inline `<code>` blocks). Validate and sanitize URL parameters used for navigation by stripping control characters and explicitly rejecting `javascript:` schemas before setting them as properties directly (`element.href = ...`).
