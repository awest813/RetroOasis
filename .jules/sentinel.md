## 2024-08-11 - [DOM-based XSS Prevention via DOM Node Creation]
**Vulnerability:** A DOM-based Cross-Site Scripting (XSS) vulnerability existed in `retrooasis/public/player.html`. The `back` URL parameter was extracted from `URLSearchParams` without any validation and injected directly into the `innerHTML` of the `#display` element as the `href` attribute of an anchor tag in the `fail()` function. This allowed attackers to execute arbitrary JavaScript by constructing a URL with `?back="><script>alert(1)</script>` or by using a `javascript:` scheme.
**Learning:** In static HTML files without a build step or automated sanitization framework, manually concatenating variables (especially user-controlled inputs like URL parameters) into an `innerHTML` string is highly susceptible to injection attacks. Even if text is escaped, URL schemes must be independently validated.
**Prevention:** To prevent DOM-based XSS when rendering dynamic content, UI components and static pages should use native DOM node creation (e.g., `document.createElement()`, `.textContent`) instead of `innerHTML` string interpolation. Furthermore, when accepting URLs for links or navigation, unsafe URI schemes must be explicitly checked and rejected (e.g., rejecting `javascript:` after stripping control characters and spaces) before assigning them via direct DOM properties (e.g., `element.href = url`).
