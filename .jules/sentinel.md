## 2026-08-07 - Refactor `fail` to prevent DOM-based XSS via `innerHTML` and `javascript:` URIs
**Vulnerability:** DOM-based XSS vulnerability existed in `retrooasis/public/player.html`. Unsanitized URL parameters (`title`, `message`, `back`) were being injected directly into the document via `innerHTML`, and the `back` parameter was being set as the `href` attribute of an anchor tag, allowing potential execution of `javascript:` payloads.
**Learning:** Legacy static HTML files outside of modern framework setups (e.g., Vite/React/Vue) often rely on manual DOM manipulation. Passing query string parameters directly into `innerHTML` is an easy trap when writing quick error or loading screens. Also, anchor tag links must specifically block `javascript:` schemas.
**Prevention:** Always use safe DOM APIs like `document.createElement()` and `textContent` instead of `innerHTML` when displaying untrusted inputs. For URLs intended for navigation, strictly validate the scheme to reject `javascript:`, or use robust URL sanitization libraries if available. Avoid writing `javascript:` to an `href` attribute by using `url.replace(/[\x00-\x20]/g, "").toLowerCase().indexOf("javascript:") === 0` pattern if URL parsing is not strictly available.
